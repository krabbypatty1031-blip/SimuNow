# 排期与任务索引

## 从当前成果出发

P0 和 P2 代码完成，P1 的 doctor/runtime 只有部分交付；无需为新主线先补安装。以下排期从路线调整后的开工计算，不重做 P2，也不承诺在给定小时内通过验证。

| 切面 | 内容 | 验收与停止条件 |
|---|---|---|
| 首个 1–2 工作日 | N1 契约/能力验证；N2 房间基本三维 | 两端非 AR 场景、坐标与选择可用；失败先处理平台能力 |
| 接下来 2–3 工作日 | N3 方向/路径/遮挡与三维整合 | 改方向、比较候选、取消与过期保护；无伪造温度场 |
| 接下来 1–2 工作日 | N5 简化流程、保存/重开与离线 QA | 没有 worker/网络仍能完成用户流程 |
| 有输入与余力时 | N4 功率/费用与简单显热估算 | 缺项明确、单位/解析例成立；不阻断气流预览发布 |
| 后续 2–4 周 | N6 实测与校准、家庭模板迭代 | 独立数据误差与适用范围；再决定增加何种求解 |

此前4–7工作日只作为最小演示切面的粗估，不能覆盖现已细化的27项任务、92项验收和发布条件。N1完成后按实际接口/平台风险重新估时，完整平台QA与签名候选另排。上表时间为拆分顺序参考，不是全部任务的交付承诺；单人按同一依赖顺序推进。

如只有 48–72 小时，冻结最小链路：已保存办公室 → 三维查看 → 改方向 → 路径/遮挡 → 一个基准加两个候选 → 建议/保存。暂缓 N4、PDF、扫描、粒子特效和物理网格；仍保留方法文字、来源、过期保护和离线验证。

## 交付门槛

数据与方法明确 → 三维可看 → 规则可复现 → 几何/单位/结果身份正确 → 同口径可比较 → 离线可保存重开 → 两端与可访问性通过 → 形成可发布候选。

其中“算法实现正确”和“真实房间预测有效”分别证明。没有独立校准也可交付明确标注的规则预览，但不能交付宣称真实舒适/节能的结论。

## 实施切面与检查点

| 检查点 | 必须完成 | 允许继续的工作/尚不能宣布的结果 |
|---|---|---|
| G1 契约可用 | N1-01/03/04，schema/值/就绪度/hash通过 | 可做N2 descriptor/N3纯规则；无executor时不声明可预览 |
| G2 任务与平台可用 | N1-02/05实际能力/调度证据 | 可做真实renderer/executor连接；缺运行时保留相应平台未验证 |
| G3 可复现预览 | N2/N3，薄盒碰撞/目标关系/当前run保护 | 进入N5常用工作流；尚不等于保存/可访问性完成 |
| G4 核心闭环 | N5-01…05 Must证据，旧包兼容/保存重开/离线/分享 | 可产开发候选；N4未实现仍允许，只保留不可用说明 |
| G5 分发候选 | N5-06安装/资源/权限/签名事实 | 正式发布需另行授权；没有签名条件时仅称开发候选 |

检查点是任务整合门槛，不新增任务ID。任何未通过项记录阻断及证据；可以推进不依赖该项的工作，不以“计划已写完”通过检查点。
