## 阶段依赖

```text
P0 工程骨架（当前）
  ├── P1 物理技术验证 ──────────────┐
  └── P2 房间模型与编辑 ───────────┤
                                  P3 任务与能耗
                                      ↓
                                  P4 CFD 与结果
                                      ↓
                                  P5 决策与报告 → 比赛交付门槛
                                      ↓
                                  UX 用户向界面（呈现，不改物理）
                                      ↓
                                  3D 视口（ADR-016，UX 之后）
                                      ↓
                                  P6 iOS 采集与现场校准
                                      ↓
                                  P7 优化、批量与产品加固
```

P1 / P2 的研发可以同时进行；P3 集成需要统一数据和已验证引擎。每个阶段文件包括目标、前置条件、功能、设计、技术、工作项、验收与降级。
阶段编号表示依赖逻辑，比赛排期允许并行；P0 工程建立不代表 P1 数值验证完成。

## 计划维护

- 状态唯一入口是 `Delivery/status.md`；工作项用固定 ID（如 P4-03）。
- 优先级：Must=比赛链路必需；Should=有时间增加；Later=产品阶段。
- 阶段验收附命令、运行 ID、截图或测量证据。
- 外部框架、标准与性能查官方现行资料；计划中的耗时和误差目标在实测后调整。
