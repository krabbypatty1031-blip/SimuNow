## 1. 审查范围与使用方式

核心结论：当前界面主要围绕数据结构与功能模块组织；用户完成“建立房间 → 调整空调 → 理解遮挡 → 比较方案”的过程被拆散在长表单、弹窗、列表和状态说明之间。应优先处理空间分配、信息层次和流程连接，再处理颜色、字体与圆角。

实机操作覆盖：工作区、二维与三维查看、对象选择与编辑、房间向导、模板、房间与门窗编辑、输入问题、预览配置、运行历史及方案比较。部分嵌套条件和数据修复分支主要通过源码检查。早期编辑器问题先在 N2 审查构建复现，最新 N3 基线核对相关布局源码；预览、历史和定性比较在最新 N3 审查构建补充实测。

未完成专项实测：深色模式、完整 VoiceOver 朗读与焦点流程、动态字号、最小窗口尺寸、最低系统运行、教室规模与长名称适配。它们属于待验证风险，不能写成已复现故障。

证据标记：

- **实机＋源码**：本轮运行中观察到现象，并核对实现。
- **源码**：由当前 UI 结构、文案或行为代码确认；不意味着所有运行环境都复现相同外观。
- **待验证**：专项验收尚未完成；需实测后确认具体问题和修复范围。

优先级：

- **P0**：裁切、溢出或关键内容不可达等直接妨碍操作的界面缺陷。此处 P0 是 UI 优先级，不是历史工程阶段 P0。
- **P1**：主要任务流程、空间利用、信息组织与状态准确性问题。
- **P2**：一致性、辅助效率、视觉细节或尚待专项确认的改进。

每项保留稳定 ID，与上一轮报告编号一一对应。未完成保持 `- [ ]`；实现后记录负责人、变更或提交、实际验证环境与证据，验收通过再勾选。源码路径是审查接入点，不是要求必须修改该文件。不得用勾选本文代替 [实施状态](Delivery/status.md) 和正式平台验收记录。

## 3. 整体布局

接入点：[WorkspaceView.swift](../Packages/SimuKit/Sources/SimuWorkspace/WorkspaceView.swift)、[Mac 入口](../Apps/SimuNowMac/SimuNowMacApp.swift)。

- [ ] **UI-001 · P1 · 左侧导航空间利用不足**（实机＋源码）
  - 问题与影响：约 210 点宽的完整侧栏只有四个入口，下方大面积空白；对象清单却位于中央画布下方，查找需要滚动。
  - 设计方向：重新明确侧栏承担导航、方案或对象结构中的哪些职责，按当前任务利用空间。
  - 验收：默认与紧凑窗口下主要内容空间充足，侧栏职责清楚，对象查找不依赖长距离滚动画布。

- [ ] **UI-002 · P1 · inspector 与当前选择无关**（实机＋源码）
  - 问题与影响：选择家具、采样点、空调或风口后，右侧仍只显示房间数、方案数及输入状态，属性另开弹窗。
  - 设计方向：让 inspector 展示所选对象的常用属性、关联结果和操作；无选择时再显示项目概览。
  - 验收：各类对象选择均更新对应内容，并清楚显示编辑对象与范围。

- [ ] **UI-003 · P1 · inspector 固定开启**（源码）
  - 问题与影响：开启状态固定，宽度 240–360 点；用户无法按查看或编辑任务收起，中央空间长期被静态信息占用。
  - 设计方向：支持明确的显示、隐藏和宽度调整，制定紧凑窗口退化方式。
  - 验收：收起、恢复后状态合理，画布和编辑内容可达，不出现挤压或裁切。

- [ ] **UI-004 · P1 · 全局顶部状态区过高且重复**（实机＋源码）
  - 问题与影响：方案、草稿可保存、缺项数和检查入口多行排列，在比较、历史和报告页面重复占据高度。
  - 设计方向：压缩公共身份与状态，页面相关信息放入各自任务区域。
  - 验收：首屏能看到页面主内容，切换页面后状态与当前任务对应。

- [ ] **UI-005 · P1 · 主操作不突出**（实机＋源码）
  - 问题与影响：创建、编辑、检查、快照藏在菜单中，中央又散布添加、放置和多种编辑按钮；下一步需要用户自行推断。
  - 设计方向：为无房间、已选对象、预览缺项、可比较等状态定义清楚的主操作。
  - 验收：每个主要状态的下一步可直接识别，不依赖探索菜单。

- [ ] **UI-006 · P1 · 工具菜单分类过宽**（源码）
  - 问题与影响：房间、使用条件、项目名称、未知摘要和快照共用“编辑与检查”；高频空间编辑与低频维护混杂。
  - 设计方向：按用户目的组织入口，将高频操作靠近其对象或任务。
  - 验收：用户能预测入口位置，常用编辑不用反复打开通用菜单。

- [ ] **UI-007 · P2 · 文件、项目与方案身份层次不清**（实机＋源码）
  - 问题与影响：窗口“未命名”、内部项目名称和“基准方案”同时存在，缺少解释，容易混淆命名和保存。
  - 设计方向：明确文档名、项目名、当前方案各自的显示与命名入口。
  - 验收：修改名称与保存文件后的身份变化可理解，不混淆不同对象。

- [ ] **UI-008 · P1 · 导航名称与页面内容不一致**（实机＋源码）
  - 问题与影响：“方案对比”先显示管理，“计算任务”主要显示本地运行附件，“分析报告”尚不可用；用户进入后要重新理解用途。
  - 设计方向：导航命名、页面首要内容和当前能力保持一致。
  - 验收：入口能准确预测页面用途，未实现能力的状态明确。

## 4. 房间工作区与对象组织

接入点：[RoomObjectsView.swift](../Packages/SimuKit/Sources/SimuWorkspace/ObjectEditor/RoomObjectsView.swift)、[RoomViewportContainer.swift](../Packages/SimuKit/Sources/SimuWorkspace/RoomScene/RoomViewportContainer.swift)。

- [ ] **UI-009 · P1 · 画布随对象长表单滚动**（实机＋源码）
  - 问题与影响：向下找空调或热源时，房间滚出视野；查看、选择和调整必须反复往返。
  - 设计方向：画布保持可见，对象清单与属性独立组织。
  - 验收：查找并编辑列表底部对象时仍能看到对应房间位置。

- [ ] **UI-010 · P1 · 预览与对象表单争夺高度**（实机＋源码）
  - 问题与影响：预览区最高 240 点，下方表单独立滚动；默认窗口首屏不能完整显示画布和工具，滚动目标不直观。
  - 设计方向：统一画布、预览控制和结果的空间关系，减少并列滚动区。
  - 验收：首屏能完成主要查看任务，滚轮作用可预测，必要控制可达。

- [ ] **UI-011 · P1 · 对象清单缺少查找与规模适配**（源码）
  - 问题与影响：所有类型纵向展开，无搜索、筛选和层级折叠；办公室已较长，教室规模风险更高。
  - 设计方向：建立可查找、可折叠的对象结构与定位入口。
  - 验收：办公室与教室场景均可快速找到指定对象，不靠逐行浏览。

- [ ] **UI-012 · P1 · 父子对象关系主要靠名称拼接**（实机＋源码）
  - 问题与影响：座位与采样点、空调与风口平铺成独立行；归属和编辑范围难以扫描。
  - 设计方向：使用清楚的层级、分组和对象类型标识。
  - 验收：能直接辨认采样点和风口属于谁，选择与展开关系稳定。

- [ ] **UI-013 · P1 · 选择反馈分散**（实机＋源码）
  - 问题与影响：画布说明、所选文字、列表和操作按钮重复表达选择，右侧又不响应，需要扫描多个区域确认。
  - 设计方向：建立统一的选择状态，联动画布、清单与属性。
  - 验收：任一入口选择后，其余区域同步且含义一致。

- [ ] **UI-014 · P1 · 多个编辑入口分工不明**（实机＋源码）
  - 问题与影响：“编辑所选属性”“编辑属性”“数值位置”和行内“编辑”并存，用户难以预测差别。
  - 设计方向：合并重复入口，对确需独立的操作给出明确名称和范围。
  - 验收：同一任务存在清楚的主要路径，按钮行为符合名称。

- [ ] **UI-015 · P1 · 子对象选择没有带来字段级编辑焦点**（实机＋源码）
  - 问题与影响：选中风口或采样点后打开父对象完整编辑器，还需寻找对应折叠字段。
  - 设计方向：保留对象归属，直接展开、定位所选子对象的常用属性。
  - 验收：从风口、控制点、采样点进入编辑后，对应字段立即可见。

- [ ] **UI-016 · P1 · 共享几何的影响提示不足**（源码）
  - 问题与影响：家具属于所有方案共享，但主要靠标题和小字说明；候选方案中修改容易误判影响范围。
  - 设计方向：在编辑位置明确共享范围和关联方案的结果新鲜度变化。
  - 验收：提交前可理解影响哪些方案，完成后结果过期状态准确。

## 5. 二维与三维查看

接入点：[RealityKitRoomViewport.swift](../Packages/SimuKit/Sources/SimuVisualization/RealityKit/RealityKitRoomViewport.swift)、[RoomPlanView.swift](../Packages/SimuKit/Sources/SimuVisualization/RoomPlan/RoomPlanView.swift)。

- [ ] **UI-017 · P1 · 三维画布难以承担主工作区**（实机＋源码）
  - 问题与影响：固定最低、理想高度，下方附带工具与说明；窗口扩大后缺少画布优先扩展策略。
  - 设计方向：按可用空间与任务分配画布尺寸，工具保持紧凑。
  - 验收：正常窗口可完整查看房间，扩大窗口明显改善空间观察。

- [ ] **UI-018 · P2 · 相机工具没有用途分组**（实机＋源码）
  - 问题与影响：旋转、缩放、俯视、重置和聚焦采用同等级网格按钮，扫描成本高。
  - 设计方向：区分连续操作、视角预设和选中对象操作。
  - 验收：常用相机操作易识别，窗口变化后分组关系不破坏。

- [ ] **UI-019 · P1 · 画布滚轮与页面滚动冲突**（实机＋源码）
  - 问题与影响：鼠标在画布上滚轮缩放，在旁边滚动表单；同一查看任务会意外改变相机。
  - 设计方向：先解决画布嵌入长滚动表单的问题，再明确缩放与页面滚动规则。
  - 验收：用户浏览清单时不意外缩放；鼠标与触控板操作均可预测。

- [ ] **UI-020 · P2 · 缺少明显的三维平移能力**（源码）
  - 问题与影响：放大后查看局部主要依赖旋转和选中聚焦，缺少直接移动视野的控制。
  - 设计方向：评估平移操作及其键盘、无手势替代；这是体验增强，不伪称已实现。
  - 验收：放大后可稳定观察局部，不改变模型输入，操作提示清楚。

- [ ] **UI-021 · P1 · 模型符号缺少图例**（实机＋源码）
  - 问题与影响：人员、座位、采样点、热源和控制点用颜色、球体区分，但含义难以直接识别。
  - 设计方向：提供按需图例，结合形状、名称和选择反馈。
  - 验收：不用猜颜色也能辨认对象类型；图例不长期挤占画布。

- [ ] **UI-022 · P1 · 二维重叠点位缺少选择消歧**（实机＋源码）
  - 问题与影响：座位与采样点可有相同 X/Y，空调与风口相近；距离选择规则不能帮助用户区分重叠对象。
  - 设计方向：提供多对象候选、循环选择或其他明确的消歧方式。
  - 验收：重叠对象均可有意识地选择，列表与画布选择结果一致。

- [ ] **UI-023 · P1 · 二维名称重叠与截断**（实机＋源码）
  - 问题与影响：办公室模板已出现标签拥挤，画布截取名称，相似长名称无法区分。
  - 设计方向：按缩放、重要程度与选择状态控制标签，提供完整名称入口。
  - 验收：长名称与密集工位仍可辨认，选中对象完整名称可读。

- [ ] **UI-024 · P1 · 二维缺少尺度与对齐参照**（源码）
  - 问题与影响：只有坐标说明，无比例尺、尺寸线、网格或对齐辅助，距离与通道宽度难以判断。
  - 设计方向：增加适量的尺度和编辑参照，明确显示辅助与真实尺寸的关系。
  - 验收：能判断对象间距离和房间尺度；辅助信息不遮挡主要对象。

- [ ] **UI-025 · P2 · 门窗符号空间含义不足**（实机＋源码）
  - 问题与影响：二维主要用彩色线段表达门窗，缺少直观类型、墙面和开启方向信息。
  - 设计方向：提供与现有模型一致的符号；未建模的开启几何不能伪造。
  - 验收：门、窗及所属墙面可辨认，符号不暗示未实现的开口气流计算。

- [ ] **UI-026 · P2 · 点击放置取消后上下文不连续**（源码）
  - 问题与影响：进入放置强制切到二维，取消没有对应恢复原查看方式，短暂任务改变查看上下文。
  - 设计方向：定义进入、完成、取消后的查看模式与选择保留规则。
  - 验收：各退出路径行为一致、可预测，不丢失必要的原视图状态。

## 6. 本地风向与遮挡预览

接入点：[AirflowPreviewPanelView.swift](../Packages/SimuKit/Sources/SimuWorkspace/Analysis/AirflowPreviewPanelView.swift)、[WorkspaceView.swift](../Packages/SimuKit/Sources/SimuWorkspace/WorkspaceView.swift)。

- [ ] **UI-027 · P1 · 首次预览提示占用过大区域**（实机＋源码）
  - 问题与影响：少量说明和一个按钮占据较高区域，留下空白并将画布向下推。
  - 设计方向：用紧凑提示连接采用假设与查看房间任务。
  - 验收：首次状态保留必要边界说明，首屏仍可使用房间画布。

- [ ] **UI-028 · P1 · “展示档案”用语含义不直观**（实机＋源码）
  - 问题与影响：用户难以理解它是一组未校准的展示假设，容易误认为文件、设备资料或历史档案。
  - 设计方向：使用准确的用户名称，解释采用后改变什么与不改变什么。
  - 验收：采用前可理解参数性质与适用边界，不误认设备实测数据。

- [ ] **UI-029 · P0 · 预览配置弹窗裁切**（实机＋源码）
  - 问题与影响：长说明在右侧裁切，“确定性 seed / UInt32”等标签接近或越出左边界。
  - 设计方向：重建标签、输入、说明和操作区布局，正确约束换行与宽度。
  - 验收：正常尺寸、长文本和字号变化下全部字段可读，取消与采用始终可达。

- [ ] **UI-030 · P1 · 算法参数缺少直观解释**（实机＋源码）
  - 问题与影响：起始半径、扩散半角、路径密度和 seed 同时出现，用户无法预测改变后的图形。
  - 设计方向：配合示意、默认值依据与渐进展开；不将假设包装为设备性能。
  - 验收：参数作用可理解，修改效果可观察，假设与校准状态清楚。

- [ ] **UI-031 · P2 · seed 与数据类型暴露在普通配置中**（实机＋源码）
  - 问题与影响：`UInt32` 等实现术语不帮助日常配置，增加认知负担。
  - 设计方向：评估普通任务是否需要修改；需要时放入高级区域并解释效果。
  - 验收：普通预览流程无需理解数据类型，确定性和追溯能力保持。

- [ ] **UI-032 · P2 · 调度实现细节出现在状态文案中**（源码）

  - 设计方向：结果与差异作为主体，管理操作紧凑且次级。
  - 验收：进入页面即能识别比较对象及其结果，管理入口仍可达。

- [ ] **UI-073 · P1 · 管理区与比较区双滚动割裂**（实机＋源码）
  - 问题与影响：上方管理按钮可被裁切，下方固定比较区仍占高度，身份、操作、结果难同时查看。
  - 设计方向：统一页面布局与滚动，必要上下文固定保留。
  - 验收：多个候选和紧凑窗口中关键内容可达，滚动目标明确。

- [ ] **UI-074 · P1 · “待计算”与已有预览结果矛盾**（实机＋源码）
  - 问题与影响：方案列表硬编码待计算，下面却已显示有效规则关系。
  - 设计方向：分别表达规则预览与其他分析方法的状态。
  - 验收：已生成、过期、缺项、取消等状态准确，未实现估算不混入已完成预览。

- [ ] **UI-075 · P1 · 比较只有总数，没有差异解释**（源码）
  - 问题与影响：不能看出哪些关注点变化、哪些输入不同及可能原因。
  - 设计方向：在同口径条件下提供逐对象关系和输入差异，不生成未经依据支持的排名。
  - 验收：相同总数但不同对象关系的方案仍可区分，档案或输入不一致明确阻断误比较。

- [ ] **UI-076 · P1 · 缺少结果的提示没有完成路径**（实机＋源码）
  - 问题与影响：缺有效预览只显示说明；名称按钮只切方案，仍停留当前页。
  - 设计方向：提供进入对应工作区、修复缺项或生成预览的有效动作。
  - 验收：可从缺结果状态完成预览并返回比较，不出现无功能按钮。

- [ ] **UI-077 · P1 · 编辑、基准与比较对象角色不清**（实机＋源码）
  - 问题与影响：顶部选择器和列表都切换方案，基准名称重复，编辑与比较范围不易理解。
  - 设计方向：清楚标识当前编辑、基准和参与比较的方案。
  - 验收：切换与设基准行为可预测，基准身份不依赖名称或排序。

- [ ] **UI-078 · P2 · 重命名弹窗标签贴边**（实机＋源码）
  - 问题与影响：单字段弹窗仍出现标签接近边界、内容比例失衡，通用表单规则不稳定。
  - 设计方向：统一简单命名弹窗的对齐、边距与操作区域。
  - 验收：长方案名完整编辑，正常字号与窗口下无越界或异常留白。

## 12. 运行历史、报告与保存状态

接入点：[NativeAnalysisHistoryView.swift](../Packages/SimuKit/Sources/SimuWorkspace/Analysis/NativeAnalysisHistoryView.swift)、[WorkspaceView.swift](../Packages/SimuKit/Sources/SimuWorkspace/WorkspaceView.swift)、[WorkspaceDocumentView.swift](../Packages/SimuKit/Sources/SimuWorkspace/Documents/WorkspaceDocumentView.swift)。

- [ ] **UI-079 · P1 · 历史以 UUID 和字节数识别**（实机＋源码）
  - 问题与影响：“载入 Run … · bytes”不能帮助判断方案、时间、输入变化与当前适用性。
  - 设计方向：优先方案、时间、方法和状态，完整身份进入详情。
  - 验收：多条运行能按用户信息辨认，完整 Run ID 与输入身份仍可追溯。

- [ ] **UI-080 · P2 · 内部资源预算占据历史页首**（实机＋源码）
  - 问题与影响：12 份、24 MiB 和进程 RAM 说明不帮助选择记录，抢占首要信息。
  - 设计方向：资源诊断移至详情，需要用户动作的资源问题才在主区提示。
  - 验收：首屏聚焦运行信息，缓存与文件保留规则仍可查。

- [ ] **UI-081 · P1 · 载入后缺少面向用户的结果路径**（实机＋源码）
  - 问题与影响：主要显示 rulePreview、checks passed、inputHash 和限制，缺少清楚的摘要与查看入口。
  - 设计方向：解释载入的是什么、属于哪个方案、如何查看，技术状态按需展开。
  - 验收：历史载入与当前预览状态不混淆，旧结果不能覆盖当前输入或伪装实时结果。

- [ ] **UI-082 · P1 · 历史没有易扫描的记录结构**（源码）
  - 问题与影响：长按钮列表缺少稳定的时间、方案、方法、检查、新鲜度与保存信息。
  - 设计方向：使用适合桌面的列表、表格或清楚记录卡片，定义排序与详情。
  - 验收：多记录可快速识别，状态独立呈现，不合并成误导的单一成功标记。

- [ ] **UI-083 · P1 · 未实现报告形成一级导航死路**（实机＋源码）
  - 问题与影响：进入只有空状态，缺少当前可查看结果的引导。
  - 设计方向：明确当前能力与已有结果路径；基线未实现报告，后续 N5 需重新审查。
  - 验收：未实现时无假生成按钮；实现后报告只使用质量与依据满足要求的数据。

- [ ] **UI-084 · P1 · 保存的不同含义表达分散**（实机＋源码）
  - 问题与影响：“草稿可保存”、结果加入项目、窗口已编辑和写盘说明各自出现，易混淆。
  - 设计方向：统一语言，分别表达保存资格、内存项目状态和磁盘保存状态。
  - 验收：可保存不等于已保存，结果加入项目不等于已写盘；系统文档保存工作流保持有效。

## 13. 输入问题、未知与假设摘要

接入点：[ValidationPresentation.swift](../Packages/SimuKit/Sources/SimuWorkspace/Editing/ValidationPresentation.swift)、[ParameterAssumptions.swift](../Packages/SimuKit/Sources/SimuWorkspace/ParameterEditing/ParameterAssumptions.swift)、[WorkspaceView.swift](../Packages/SimuKit/Sources/SimuWorkspace/WorkspaceView.swift)。

- [ ] **UI-085 · P1 · 问题总数不区分能力与任务**（实机＋源码）
  - 问题与影响：办公室模板显示 64 项待补充；保存、几何预览、能耗和舒适依据混合，无法判断下一步。
  - 设计方向：按方法、对象和严重程度组织，明确当前任务真正的阻断。
  - 验收：64 是审查样本而非固定目标；不同输入下的可用能力、阻断项和补充项均准确。

- [ ] **UI-086 · P1 · 定位没有到具体字段**（实机＋源码）
  - 问题与影响：只进入父对象编辑器，仍需展开和滚动寻找，未完成定位承诺。
  - 设计方向：字段级定位、展开、聚焦，并保留返回问题列表的路径。
  - 验收：各可定位问题直接显示相关字段，不能定位的条目解释原因。

- [ ] **UI-087 · P1 · 错误混入结构路径和索引**（实机＋源码）
  - 问题与影响：部分英文属性名未转换，“第 1 项”不能替代对象名称。
  - 设计方向：主文案用对象名与参数名，原路径作为诊断详情保留。
  - 验收：常见字段完整可理解，长名称与重排对象不会错误定位。

- [ ] **UI-088 · P1 · 未知摘要按数据路径组织**（实机＋源码）
  - 问题与影响：房间、各方案和设备混合，缺少筛选、分组和搜索，适合开发核查却不便日常理解。
  - 设计方向：按当前方案、对象、方法与来源组织，支持范围切换。
  - 验收：默认范围清楚，可查看全项目但不会把其他方案误认当前缺项。

- [ ] **UI-089 · P1 · 未知摘要没有直接修复动作**（源码）
  - 问题与影响：读到未知后需关闭摘要、找对象、打开编辑，流程重复。
  - 设计方向：连接对应字段与修复，完成后回到原摘要位置。
  - 验收：可连续修复多项，状态实时准确，取消编辑不丢失阅读位置。

- [ ] **UI-090 · P1 · 旧计算文案与当前能力不一致**（源码）
  - 问题与影响：部分说明仍笼统写计算引擎未接入，忽略已实现本地规则预览。
  - 设计方向：统一规则预览、简化估算与后续复核的名称和实现状态。
  - 验收：各页文案与实际注册能力一致，方法检查通过不等于物理验证。

## 14. 视觉一致性、Mac 操作与专项验证

接入点：SimuWorkspace 各共享 View、[SimuVisualization](../Packages/SimuKit/Sources/SimuVisualization)、[SimuDesignSystem](../Packages/SimuKit/Sources/SimuDesignSystem)、[Mac 入口](../Apps/SimuNowMac/SimuNowMacApp.swift)。

- [ ] **UI-091 · P1 · 留白与局部拥挤并存**（实机＋源码）
  - 问题与影响：导航和静态统计空白多，参数、错误和说明密集，空间没有按任务价值分配。
  - 设计方向：建立全局密度与空间层次，优先容纳主任务。
  - 验收：核心内容突出，说明可读，长项目不靠无限增加页面高度解决。

- [ ] **UI-092 · P2 · 操作视觉权重相近**（实机＋源码）
  - 问题与影响：高频、辅助、管理和危险操作缺少足够层级，主要靠阅读全部按钮辨认。
  - 设计方向：统一主次操作、危险操作与不可用状态的样式和位置规则。
  - 验收：主操作易识别，删除不与主任务竞争，状态不只靠颜色传达。

- [ ] **UI-093 · P1 · 长说明代替了结构表达**（实机＋源码）
  - 问题与影响：共享范围、坐标、顺序、依据和保存机制都依赖小字段落，阅读负担高。
  - 设计方向：先通过布局、分组和状态表达关系，再补充必要文字。
  - 验收：减少重复说明仍能理解规则，关键边界和证据完整保留。

- [ ] **UI-094 · P2 · 术语与命名缺少统一规则**（实机＋源码）
  - 问题与影响：中文、代码字段、UUID、英文状态、数据类型混用，用户无法辨认哪些必须理解。
  - 设计方向：制定用户术语、专业单位和诊断信息的使用规则。
  - 验收：同一概念各页同名，技术细节可达但不抢占主流程。

- [ ] **UI-095 · P2 · 高频操作缺少完整键盘工作流**（源码）
  - 问题与影响：已有撤销、重做与系统文档能力，但查找、聚焦、切换查看、编辑所选和重新预览缺少清楚入口与提示。
  - 设计方向：定义 App 常用命令与快捷键，保留系统标准行为。
  - 验收：核心流程可用键盘完成，焦点稳定，不与系统命令冲突；不得误称现有 Cmd-S 不存在。

- [ ] **UI-096 · P1 · 长名称、多对象与紧凑窗口适配风险**（待验证；已有裁切为关联证据）
  - 问题与影响：固定弹窗、多个滚动区、长字符串和名称截断可能在教室规模与最小窗口放大。
  - 设计方向：用真实规模、长名称和可缩放窗口验证后确定具体布局修复。
  - 验收：默认 1280×800 与声明最小 900×600 窗口、长名称和教室规模均检查；每项故障保存复现与修复证据。

- [ ] **UI-097 · P1 · 可访问性完整流程尚未验证**（待验证）
  - 问题与影响：已有文字状态、列表与无手势替代；多层折叠、重复编辑按钮、长摘要和动态结果仍需检查朗读与焦点。
  - 设计方向：实测 VoiceOver、键盘、动态字号和 Reduce Motion，不凭标签存在判断完成。
  - 验收：核心流程可完成，名称、所属对象、方法和结果可理解；动态更新不丢焦点，静态路径替代有效。

- [ ] **UI-098 · P1 · 深浅色与视觉编码专项未完成**（待验证）
  - 问题与影响：已有部分主题适配，模型颜色、选择、路径和遮挡在深色下的识别度尚未实测。
  - 设计方向：检查颜色、形状与文字共同传达状态的效果。
  - 验收：深浅色各类状态可辨认，选中与遮挡不只靠颜色，无不当真实风速或温度暗示。

- [ ] **UI-099 · P1 · 导入与异常恢复缺少统一过程表达**（源码）
  - 问题与影响：JSON、迁移、EPW 和修复采用不同弹窗提示，处理文件、阶段、去向与返回位置不连贯。
  - 设计方向：统一过程身份、进度、成功结果和恢复入口，保留各格式的实际约束。
  - 验收：成功、取消、迁移和损坏文件各路径可理解，目标项目/方案准确，合法原数据不静默丢失。

## 15. 跨页面设计约束与实施顺序建议

以下为原审查的实施顺序建议；本轮实现与仍待验证的范围见实现记录，不能据源码状态判定平台验收通过：

1. 先修 UI-029、041、048、053 的裁切与溢出，确认标题、字段和关键操作可达。
2. 再调整工作区：画布持续可见，侧栏与 inspector 各有明确职责，减少争夺高度的独立滚动区。
3. 建立统一选择与字段定位：画布、清单、属性、问题与结果使用同一对象身份，形成连续操作。
4. 优先简化位置和方向调整；来源、未知和专业参数采用渐进展开，不丢失已有数据。
5. 按实际方法区分就绪度、运行状态、方法检查、结果依据、新鲜度与保存。
6. 将比较差异和运行身份置于管理、版本与诊断细节之前。
7. 统一弹窗、按钮、术语、说明和错误反馈，再做深浅色、键盘、字号和 VoiceOver 验收。

必须继续保留的基础与边界：

- 模型与显示分离，显示层不重算热负荷或推荐；共享模型维持米制、右手 Z-up 与集中坐标转换。
- 设定温度、送风温度、制冷量、电功率、风量和速度分别建模并标注单位。
- 未知、来源、假设和不确定区间可保存；未知不默认为零，展示默认值不伪装设备实测。
- 本地规则只表达假设路径和遮挡；不暗示真实逐点风速、温度、舒适、满意率或节能结论。
- Run ID、scenario ID、输入哈希、方法版本和不可变快照保留；旧任务不覆盖当前方案。
- 任务成功、方法检查、结果依据、新鲜度和磁盘保存独立；“可保存”不等于“已保存”。
- 比较只使用当前有效、同口径结果；质量失败、过期或不满足输入要求的记录不得用于有效推荐与报告。
- 未实现功能使用明确不可用状态，不添加无功能按钮；未来计划与 debug/test executor 不写成产品已实现能力。
- 保留系统文档工作流与已实现的撤销；共享 UI 改动需验证 Mac/iOS，不以 Mac 外观完整替代其他平台或物理验收。
