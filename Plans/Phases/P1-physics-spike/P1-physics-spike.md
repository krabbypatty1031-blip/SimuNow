# P1：物理技术验证

## 目标与前置

证明一个参数化房间能从命令行生成真实 U/T 场、冷负荷与输出；前置为统一的初始输入形状。比赛 4–12h 为首个决策窗口。

## 功能、设计与技术

固定 Linux OpenFOAM 运行环境、单区 EnergyPlus、参数化网格、PyVista 后处理、可重复脚本。
先明确发行分支和算例来源，选择稳态浮力求解器与匹配的湍流/近壁面策略。矩形流体域和简化送回风，逐步增加热源与家具。

## 工作项

| ID | 工作 | 技术/输出 |
|---|---|---|
| P1-01 | 固定 CPU 架构、引擎版本、容器/VM，记录内存 | runtime manifest 与 doctor 能力 |
| P1-02 | 跑公开浮力基准、增加室内非等温射流基准 | 原始数据对比、误差与来源 |
| P1-03 | 输入转 case、网格、checkMesh、求解、采样 | 一键脚本及运行目录 |
| P1-04 | 单区域天气/热源/理想负荷或设备模型 | 代表日输出与单位核对 |
| P1-05 | 测粗/中网格时间、内存、质量与能量 | 性能表、可行算例规模 |

## 验收

同输入可复算；单位与重力正确；送回风质量和能量守恒；监测点稳定；产生切片与座位样本；L1 热源与 L2 一致。
基准验证说明模型适用范围，不能用自然对流基准代替送风射流验证。至少取得一个公开基准比较证据，三网格与现场验证在后续阶段完善。

## 风险与降级

12h 尚未稳定时减少几何与支持变量，沿用已验证模板；调整网格和执行位置。缓存只能是本团队真实运行、输入匹配的结果。
若 L2 完全不可用，明确退到 L0/L1，无逐点结论，并记录偏离比赛核心目标；不能用动画代替物理。
