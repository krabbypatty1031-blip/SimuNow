## N4实施中的根审查

以下是草稿早审边界；N4最终实现及对应解析式/反例测试已通过，根最终201项共享Swift全测复验通过。它们不代替真实平台卡片操作，实际未验项见台账。

| 边界 | 要求与反例 |
|---|---|
| 未采用功率片段 | 请求[0,60)为已知功率，[60,120)unknown不能阻断首段；结构非法仍全量拒绝。basis确认及measurementPeriod同样只影响相交片段。 |
| 能力范围筛查 | 显热需求900W、名义能力1000W但能力范围500…1500W应不可稳定筛查；不能只比较名义能力。total×SHR端点亦须传播。 |
| 未展开热输入范围 | 热输入bounds未列sensitivity、关系缺失或超过2个时要求补配置/缩范围；不得把名义值重复填成零宽包络。 |
| 费用区间 | tariff.rate带bounds时，费用下/上界须包含其端点；不能只展开power范围后忽略价格范围。 |
| 比较的决策变量及basis | 不同功率/方向须声明对应变量；同basis仅时间分割不同不应误阻断，不相交片段basis不参与采用口径。背景/目标范围不同给具体不可比较理由。 |
| run与项目绑定 | 导入codec须同时核对manifest项目、request snapshot项目和调用方项目；合法另一个项目的run不能只改manifest就进入当前项目有效历史。 |
| 重复执行与显示精度 | 每次明确执行使用新runID，不能重复提交prepared旧ID；在途点击有明确策略。费用最终显示按配置精度格式化，详情保留精确Decimal与上下界。 |
| 简化结果checks与载荷一致性 | passed功率不能仅含小计/total缺失，结果片段的完整窗口和积分需自洽；显热ledger/total/max(0,Q)/范围需自洽。结构schema不能替代这种检查，也不能把method检查包装成现实准确度。 |
| Decimal极小值的SDK行为 | 根在本机Swift6.4/Foundation实测`Decimal(1e-100) × (Decimal(1)/Decimal(60000))`的doubleValue约1.67e151，而数学值约1.67e-105；isNaN为false，NSDecimalMultiply状态亦为noError。费用必须明确非零输入数值支持下限或使用额外数量级检查，不能仅以isNaN/运算状态保证安全；合法0、实际小额与最后格式化仍需验证。 |
